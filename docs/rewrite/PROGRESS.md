## Decisions

Recorded by the implementing agent; each says why.

1. **Tool versions are the latest stable on 2026-10-18**, not DESIGN §3's pins (which were a floor): hono 4.13.13,
   zod 4.6.7, @hono/zod-validator 0.9.1, drizzle-orm 0.45.4, drizzle-kit 0.31.11, wrangler 4.151.1,
   typescript 7.0.2, @biomejs/biome 2.5.15, fast-check 4.10.2, tsx 4.23.15, pnpm 12.14.0.
2. **`@cloudflare/vitest-plugin` 1.4.4 + vitest 5.0.5 instead of `@cloudflare/vitest-pool-workers` + vitest 4.**
   The pool package is deprecated and renamed; the plugin's peer range is `vitest ^4.1.0 || ^5.0.0`, so the latest
   vitest is supported. The plugin has no `isolatedStorage` option: storage is isolated per test file, and tests
   create their own users rather than relying on an empty database (CONVENTIONS.md).
3. **No `PLAN` var and no `lib/budget.ts` plan branching** (OWNER-DECISIONS: Workers Paid). Limits that DESIGN put in
   the budget table become plain constants in the module that uses them, at the Paid values.
4. **`MAILER` is `cloudflare` | `console`** with the `send_email` binding `EMAIL`; Brevo and `BREVO_API_KEY` are gone.
5. **Runtime types**: `wrangler types --env-file .dev.vars.example` generates `worker-configuration.d.ts` (committed;
   CI runs `--check`). The env file is passed explicitly so a developer's leftover Python `.env` never leaks into
   the generated `Env` type; tests also disable `.env`/`.dev.vars` loading for the same reason.
6. **Resource ids in `wrangler.jsonc` are zero-UUID placeholders** until the cutover unit creates the databases
   (`wrangler d1 create pacestreak --location apac`). D1's location hint is a creation-time flag, not a config field.
7. **gitleaks scans the working tree** (`gitleaks dir`), not history: the Python history predates the rule and is
   not what this branch ships. Runs from the pinned container image, no licence key needed.
8. **The Python tree is deleted on `next`**; `docs/rewrite/python-tests/` keeps a copy of the pytest suite for the
   name-parity script and as porting reference. Old code: `git show main:<path>`.

9. **Schema (F1)**: 69 tables = the 60 ported + `sessions`, `rate_counters`, `job_leases`, `import_jobs`,
   `export_jobs`, `stat_days`, `stat_weeks`, `records_best`, `sync_seq`. Column names are snake_case through Drizzle's
   `casing: "snake_case"` (set once in `drizzle.config.ts` and `src/db/client.ts`).
10. **No `WITHOUT ROWID`**: drizzle-kit cannot emit it, and hand-editing generated migrations would break the drift
    check. `stat_days`, `stat_weeks`, `records_best` are rowid tables with a composite PRIMARY KEY (one extra
    autoindex per table; lookups still use the PK index).
11. **`user_stats.rev` is both the recompute concurrency token and the ETag version** (DESIGN named two columns
    that always change together).
12. **Auth tables are redesigned, not ported** (no data to keep): `refresh_tokens` hangs off `sessions`
    (cascade), `one_time_tokens.code_hmac` and `recovery_codes.code_hmac` hold HMACs, `users.totp_secret` holds
    AES-GCM `v1.<iv>.<ct>`.
13. **`sync_seq` and `job_leases` are self-seeding UPSERTs**; no seed migration. `stat_days`/`stat_weeks`
    `chain_id` is a chain id or `""` for the whole-life aggregate, so it is not a foreign key.
14. **Indexes**: per-user name lookups use composite `(user_id, name_fold)` indexes instead of a lone `user_id`
    index; a schema test asserts every foreign key column leads some index and every fold column (except
    `journal_days.note_fold`, which is only searched with `contains`) is indexed.
15. **D1 refuses pragma table-valued functions** (`pragma_foreign_key_list(x)` in a join gives `SQLITE_AUTH`);
    plain `PRAGMA foreign_key_list("x")` statements work, so the schema tests batch one per table.

16. **Session write guard = an aborting statement, not a predicate on every write.** DESIGN §5 asked for each write
    to carry `EXISTS(live session)`; that cannot be enforced generically for builder-made INSERTs. Instead statement 0
    of `AuthedBatch.write` is `INSERT INTO batch_guards (session, rate_limit) SELECT NULL, 0 WHERE NOT EXISTS (live
    session)`: nothing is inserted while the session is live, otherwise the NOT NULL violation aborts and rolls back
    the batch (D1 batches are atomic; G-3 test). `guardError` maps it to 401; the `rate_limit` column gives P1-GUARD
    the same tool for 429. One new table (`batch_guards`, never holds a row): 70 tables.
17. **`runBatch` instead of drizzle's `db.batch`**: drizzle-orm 0.45 crashes on `db.run(sql\`...\`)` with parameters
    inside a batch (`stmt.bind` of undefined). `runBatch` prepares each query the same way and maps results with
    drizzle's own `mapResult`; tested.
18. **Batched joins must alias duplicate column names**: D1 returns batch rows as objects keyed by column name, so
    `users.id` and `sessions.id` in one select collapse. The auth statement aliases `session_id`; CONVENTIONS.md
    makes it a rule.
19. **Own validation middleware (`lib/validation.ts`) instead of `@hono/zod-validator`**, which turned malformed JSON
    into a 400 and could not reproduce FastAPI's missing-body/`json_invalid` 422s. Dependency removed.
20. **No `lib/budget.ts`** (WORKPLAN F2 lists it): its only purpose was Free/Paid branching (decision 3).
21. **`requireVerifiedEmail`** is config, true in production/staging and false in development/test (Python's
    default was false, production set it true).
22. **Request ids** are `cf-ray`, or a random UUID when absent (tests, `wrangler dev`).
23. **Bundle**: 181 KiB gzipped with only the foundation (zod 4 + drizzle + Hono + the schema); budget 400 KiB.
    If modules push it near the limit, `zod/mini` is the first lever.

24. **vitest 5 has no `bench()`**: CPU benches are tests in `test/bench/*.bench.ts` using a small harness
    (`benchCase`, median per op vs 0.6 x budget), run by `pnpm bench` (BENCH=1) and excluded from `vitest run`.
    workerd's clock advances during local tests, so the timings are real.
25. **Pytest parity is a ratchet**: `test/parity.json` `maxMissing` (now 291 of 293 names; the suite has 293, not
    285). A TS title equal to the name without `test_`, or containing `test_name`, counts; `// parity-dropped:
    test_name: reason` drops one. CI fails if missing exceeds the ratchet or a title names an unknown test.
26. **Outbound fetch is blocked in tests** unless mocked (`mockFetch`), replacing the removed `fetchMock`.
27. **`X-D1-Round-Trips` response header in the test environment only**, so route tests assert round-trip budgets
    through the real Worker.
28. **Heavy-user ids are deterministic UUIDv7-shaped strings** from a seeded PRNG, so the data set is identical on
    every run; `pnpm seed:heavy` emits the same rows as SQL for a local D1.

### P1 decisions (2026-10-18)
- R2: only JPEG/WebP/PNG accepted (as Python); WebP check also needs `WEBP` at byte 8, PNG full 8-byte signature (fix, see CHANGES). Bucket name passed in; photos module adds an `R2_BUCKET` var.
- Rate limits: rejected calls still count (Python parity); fixed windows aligned to window length (slowapi-style) instead of first-hit.
- Mailer: own MIME builder for `send_email`; header CR/LF refuses the send; 10 MiB attachment cap.
- Crypto: PBKDF2 100k ≈ 23 ms wall in local workerd (G-1 cpuTime on staging still owed). JWT checks follow PyJWT. AES-GCM supports AAD (auth should bind user id).
- Push: push lib returns outcomes, notifications module applies them in its batch; guard re-run at send time.
- Jobs: one lease per trigger (240 s), shared `scheduler` heartbeat; stale threshold 900 s (was 360 s).
- Heavy: all readers resumable from any byte offset with JSON state; FIT errors keep partial data.
- Catalog: data generated from Python modules and verified deep-equal.
